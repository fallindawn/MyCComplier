1. 项目概述
================================================================================

本项目实现了一个C语言编译器，具有以下功能：
✓ 词法分析（使用Flex实现）
✓ 语法分析（使用Bison实现）
✓ 抽象语法树（AST）构建
✓ 符号表管理
✓ 四元式中间代码生成

项目特色：
- 完整支持基本C语言语法
- 实现了变量声明、赋值、循环、条件等语句
- 支持多种运算符（算术、关系、逻辑）
- 生成标准的四元式中间代码

================================================================================
2. 编译步骤
================================================================================

【第一步】进入项目目录
cd myCComplier

【第二步】运行编译脚本
Windows: powershell -ExecutionPolicy Bypass -File build.ps1
或
Linux/Mac: make

编译过程会：
1. 使用 Flex 生成词法分析器 (lex.yy.c)
2. 使用 Bison 生成语法分析器 (y.tab.c, y.tab.h)
3. 编译所有 C 源文件
4. 链接生成可执行文件 (compiler.exe 或 compiler)

================================================================================
3. 运行编译器
================================================================================

基本用法：
Windows: .\compiler.exe <C_source_file>
Linux/Mac: ./compiler <C_source_file>

示例：
.\compiler.exe test\test1.c
.\compiler.exe test\test2.c

【测试 1】基本变量声明和赋值
---------
文件：test\test1.c
内容：

  int b;

  a = 10;
  b = 20;
  c = a + b;
  printf(c);

运行命令：.\compiler.exe test\test1.c

关键演示：
✓ 词法分析正确识别所有token
✓ 语法分析构建正确的语法树

5. 输出结果详解
================================================================================

【词法分析结果】
格式：
  No.  Token Type       Lexeme             Line
  ----  -----------     ------             ----
  1     KEYWORD_INT     int                1
  2     IDENTIFIER      a                  1
  3     SEMI            ;                  1

说明：
- No.：token 序号
- Token Type：token 的类型（关键字、标识符、运算符等）
- Lexeme：token 的字面值（源代码中的实际文本）
- Line：token 在源代码中的行号

【抽象语法树（AST）】
格式：
  PROGRAM
    DECL_LIST
      DECL
        ID(a)
      DECL
        ID(b)
    STMT_LIST
      ASSIGN
        ID(a)
        NUM(10)

说明：
- 树形结构显示程序的语法结构
- 缩进显示树的层级关系
- 每个节点显示其类型
- 叶子节点显示具体的值（如 NUM(10)、ID(a)）

节点类型说明：
- PROGRAM：整个程序
- DECL_LIST：声明列表
- DECL：变量声明
- STMT_LIST：语句列表
- ASSIGN：赋值语句
- IF/WHILE/FOR：控制语句
- WRITE/READ：输入输出
- BINOP/UNOP：二元/一元运算
- NUM：数字常量
- ID：标识符

【符号表】
格式：
  Name                           Type            Line
  ----                           ----            ----
  a                              int             2
  b                              int             3
  c                              int             4

说明：
- Name：变量名
- Type：变量类型（目前只支持 int）
- Line：变量声明所在的行号

【中间代码（四元式）】
格式：
  Num  Op     Arg1                 Arg2          Result
  ---  --     ----                 ----          ------
  0    DECL   a                                  
  1    =      10                                 t0
  2    =      t0                                 a
  3    +      a                    b             t1
  4    =      t1                                 c

说明：
- Num：四元式序号
- Op：操作符（=, +, -, *, /, %, ^, ==, !=, <, >, <=, >=, &&, ||, !）
- Arg1：第一个操作数
- Arg2：第二个操作数
- Result：结果

四元式格式说明：
- (Op, Arg1, Arg2, Result)
- 对于一元运算：(Op, Arg1, _, Result)
- 对于赋值：(=, 值, _, 变量)
- 临时变量：t0, t1, t2, ... 自动生成

6. 编译器支持的语法
================================================================================

【数据类型】
✓ int - 32位整数

【声明】
✓ int var_name;
✓ int var1, var2, var3;  (不支持，需逐个声明)

【语句】
✓ 赋值：var = expression;
✓ 输入：scanf("%d", &var);
✓ 输出：printf(expression);
✓ if-else：if (condition) { ... } else { ... }
✓ while：while (condition) { ... }
✓ for：for (init; condition; update) { ... }
✓ 复合语句：{ statement_list }

【运算符优先级（从低到高）】
1. ||  (逻辑或)
2. &&  (逻辑与)
3. == != (关系运算)
4. <  >  <=  >= (关系运算)
5. +  -  (加减)
6. *  /  %  (乘除模)
7. ^  (乘方)
8. !  -  (逻辑非、负号，右结合)
9. ()  (括号)

【运算符】
◎ 算术：+ - * / % ^
◎ 关系：== != < > <= >=
◎ 逻辑：&& || !
◎ 赋值：=

7. 已知限制与改进空间
================================================================================

【当前限制】
- 仅支持 int 类型，不支持 float、double、char 等
- 不支持数组和指针
- 不支持函数定义（仅支持 scanf/printf 调用）
- 不支持结构体、联合体等复杂类型
- 不支持预处理指令（#define, #include 等）
- 不支持多维数组

【可能的改进】
1. 数据类型扩展
   - 添加 float、double、char 支持

2. 高级特性

3. 代码优化

10. 故障排除
================================================================================

【问题】编译失败："command not found: gcc/flex/bison"
【解决】安装必要的工具包（参考第9节）

【问题】Yacc 报错："conflicts: shift/reduce"
【解决】这是预期的，Bison 使用 LALR(1) 分析可能产生移进/归约冲突，
       这对该文法是可接受的

【问题】编译器报"未声明的变量"错误
【解决】确保在使用前声明所有变量

【问题】中间代码生成异常
【解决】检查输入文件的语法是否正确
